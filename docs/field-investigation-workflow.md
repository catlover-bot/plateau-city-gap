# Field investigation workflow

## 公開6段階

1. **候補一覧**: 目的の異なる3件から人が選ぶ。
2. **候補brief**: 主要3値、既知/未知、出典、495/286/218/候補順位の母数を確認する。
3. **PLATEAU現地文脈**: 収録がある候補だけ500m→建物→道路→地形へ具体化する。未収録は不足のまま扱う。
4. **確認項目**: data gap・分析上の仮定・PLATEAU文脈を理由付き項目へ決定論的に変換する。
5. **現地調査票**: 主要数値、PLATEAU、不足、出典、状態、優先度、担当、期限、メモ、GPS、写真参照を人が編集し、端末内に保存または印刷する。
6. **庁内調査サマリー**: 候補理由、PLATEAU、不足、確認状態、出典、限界を共有し、実回答を得た後だけ自治体レビュー結果・原文を内部記録する。

詳細分析は6段階を完了した後にだけ開く。既存の高度分析、シナリオ、検証、Municipal Serviceは削除しない。

## 候補区分

| 区分 | 意味 | 次の行動 |
|---|---|---|
| 分析上の候補 | 人口・交通・医療条件から追加確認価値を人が仕分ける | screening |
| 詳細調査例 | PLATEAU建物・道路・地形まで確認できる | 調査票まで具体化 |
| データ確認候補 | 分析上は気になるが詳細情報が不足 | 不足情報を先に確認 |

3区分を同じランキングとして表示しない。単一スコアで政策順を決めない。

## 人による仕分け状態

- 未確認
- 追加調査
- 既存施策を確認
- データ不足
- 現地確認中
- 確認済み
- 対象外

初期状態は未確認。自動分析は確認済みへ変更できない。

## 確認項目の生成契約

ルール版: `maizuru-field-check-1.0.0`

各項目は次を必須とする。

- category: 交通 / 歩行環境 / 医療・介護 / 候補地点 / 地域事情
- label
- reason
- origin: data gap / analysis assumption / PLATEAU context / human
- source gap IDs
- default priority

自治体レビュー結果は別に次の状態を持つ。

- 未確認
- 確認する価値がある
- 一部有用
- 既存施策で対応済み
- 地域事情と異なる
- データ不足
- 対象外

初期値は未確認で、実回答欄は空欄。入力後も価値仮説を自動で `SUPPORTED` にしない。

初期28項目はルールから再生成可能。人が追加した項目は `origin=human` として区別する。生成できるのは「何を確認するか」までで、確認結果は人が入力する。

## public / internal境界

Public:

- 候補ID・500mメッシュ
- 候補理由と主要3値
- PLATEAU収録状況
- data gap
- 初期確認項目のlabel/reason/origin/lineage
- 出典・年次・限界

Internal:

- 担当
- 期限
- 状態
- メモ
- GPS
- 写真参照
- 自治体回答原文

Internal調査票はIndexedDBへ保存し、サービスワーカーのpublic runtime cacheへ送らない。URL共有には内部内容を含めない。

## 通信なしと競合

公開シェル、必須実データ、選択済みSpatial Packをサービスワーカーへ保存する。内部調査票は端末内IndexedDBへ保存する。既存Municipal Serviceの同期ではHTTP 409を明示的競合として保持し、silent last-write-winsを許可しない。

## 判断境界

- 距離は収録点までの直線距離で、徒歩距離・所要時間ではない。
- 道路面は歩行可能性を保証しない。
- DEMは歩行負担・危険度の測量結果ではない。
- 候補は政策推奨・危険判定・実施効果予測ではない。
- 自治体レビューは `AWAITING_MUNICIPAL_REVIEW`。
- 人による初見テストは `AWAITING_HUMAN_TEST`。
- 時間・費用ベースラインは `BASELINE_NOT_COLLECTED`。
